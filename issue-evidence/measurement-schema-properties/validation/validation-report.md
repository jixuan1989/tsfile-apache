## Java 兼容

- 360 组 Schema：10 种普通标量类型 × Java 的 6 种压缩标记 × 6 组属性。Java 生成，C++ 读取后序列化，再由 Java 校验所有字段、属性及逐字节一致性。此矩阵验证 Schema 格式。
- 属性包含空键/值、多属性、UTF-8/emoji、4097 字节的长值及 64 个键值对。
- 完整 TsFile：Java 和 C++ 双向写读带属性的 16 列 FLOAT/PLAIN 表，各 64 行，校验全部 1024 个值；Java 同时校验全部列的属性。
- 原生文件夹具：C++ 读取 Java 生成的 123 个文件；Java 读取 C++ 生成的 117 个文件。夹具包含 UNCOMPRESSED、LZ4、ZSTD 和 LZMA2 的实际数据压缩。Windows 生成的 CSV 清单仅统一为 LF，TsFile 文件字节未改动。
- 新鲜 C++ 对象写出的含 NUL 属性共 36 字节，与 Java 完全相同，并由 Java 成功读回。

另行记录的既有问题：`SerializationUtil::read_str` 读取含 NUL 的字符串时会截断。原版和修复版都将 3 字节 `a\0b` 读成 1 字节，已有对照证据。该读取问题保留在后续候选队列；当前验证的写入格式保持完整。

## 性能

同机、同 MSVC 14.50 Release 配置，原版头文件及静态库在改动前保存。每种变体先运行 2 次预热，再执行 25 轮交错顺序测量；子进程固定到相同 CPU 掩码 4。记录耗时、吞吐、P95 和峰值工作集。性能测量期间本任务的构建和覆盖率收集均已结束。

| 比较 | 基线中位耗时 ms | 修复中位耗时 ms | 配对耗时比中位数 | 配对比 95% bootstrap CI |
|---|---:|---:|---:|---|
| 空属性序列化：原版有效输出基线 | 55.147 | 55.101 | 0.9993 | [0.9955, 1.0019] |
| 无属性表写入：原版有效输出基线 | 18.627 | 18.614 | 0.9915 | [0.9749, 1.0109] |
| 单属性：合法格式手工参考实现 | 80.997 | 77.900 | 0.9641 | [0.9575, 0.9653] |
| 64 属性：合法格式手工参考实现 | 152.503 | 152.164 | 0.9975 | [0.9952, 1.0012] |

空属性每轮序列化 1,000,000 次；单属性同样为 1,000,000 次；64 属性为 100,000 次。表写入为 50,000 行 × 16 列 FLOAT/PLAIN/UNCOMPRESSED，计时包含创建文件、write_table 和 close；Tablet 构造及完整读回校验在写入计时之外。比率是每轮修复/基线耗时比的中位数，与两列中位数直接相除有所不同。

原版空属性和表写入为合法输出基线，两项均未观察到退化。空属性的工作集中位峰值均为 4,972,544 字节；表写入为原版 15,777,792、修复版 15,773,696 字节。

原版非空属性输出不完整。单属性及多属性性能使用显式写出全部键值的合法格式参考实现作比较；参考实现源码和测量原始数据已保留。该项单独列示。
